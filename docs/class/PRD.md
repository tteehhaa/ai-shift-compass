# PRD — AI Life Shift

작성일: 2026-09-08
버전: 0.1 (출시 전)

**한 줄 정의**: 내가 돈 받고 하는 일 위에 AI를 얹어 보고, 뭘 맡기고 뭐에 집중할지 3분 안에 알려 주는 무료 진단.

---

## 1. 문제

### 1.1 핵심 불편

타깃은 "AI가 내 일을 어떻게 바꾸는가"를 알고 싶은데, 지금 시장의 답은 두 극단뿐이다.

- **너무 일반적**: 직업명 하나 넣으면 위험도 퍼센트가 나오는 계산기. 결과가 통계 평균이라 내 얘기가 아니다.
- **너무 무겁다**: 강의·컨설팅. 뭘 배울지 이미 정한 사람용이고, 시간과 돈이 든다.

그 사이에 **"내 업무 목록 위에서, 뭘 맡기고 뭘 지킬지"**를 짚어 주는 것이 없다.

### 1.2 불편 5가지 (`시장조사요약서.md` 요약)

| # | 불편 | 상태 |
|---|---|---|
| 1 | 직업 단위 진단이 안 와닿음 | 가설 |
| 2 | 도구는 많은데 뭐부터인지 우선순위를 못 정함 | 가설 |
| 3 | AI를 써도 시간이 줄었는지 체감·증명 안 됨 | 가설 |
| 4 | 시간이 남아도 돈으로 연결 안 됨 | **가설 — 최우선 검증** |
| 5 | 정보에 과장·공포가 섞여 뭘 믿을지 모름 | 가설 |

> **중요**: 5개 모두 인터뷰 미실시 상태의 가설이다(`시장조사_타겟페인.md`: 가설 14 / 확인후보 9 / 본인판단 5). 이 PRD는 미검증 가설 위에 서 있으며, 인터뷰 결과에 따라 개정될 수 있다.

## 2. 타깃

### 2.1 포함

| | A. 프리랜서·1인사업자 | B. 이직을 준비하는 직장인 |
|---|---|---|
| 왜 이 층인가 | 시간 절감이 곧 처리 건수, 즉 매출 | 이직은 연봉이 걸린 결정. 이미 이력서·컨설팅에 지출하는 습관 있음 |
| 입력 성립 | ✅ 현재 업무 있음 | ✅ 현재 업무 있음 |
| 원하는 결과 | "뭘 자동화하면 한 건 더 받나" | "내 업무 중 AI에 안 밀리는 게 뭔가" |
| 지불 지점 (향후) | 자동화 셋업 대행 | 업무 기반 포지셔닝·이력서 재작성 |

### 2.2 제외와 그 이유

- **일반 직장인(이직 의사 없음)** — "빨리 끝내면 일만 더 온다"는 가설 때문. **단, 이 가설 자체가 미검증**이므로 검증 후 복귀 가능
- **취업준비생·진로 탐색층** — 현재 업무가 없어 입력이 성립하지 않음. 희망 직업명을 받는 순간 기존 계산기와 동일해지고 차별점이 사라짐
- **기업·조직 단위** — 별도 시장. 중진공 AX자가진단 등이 이미 존재

## 3. 가치 — 우리만의 해결책

### 3.1 차별점 한 문장

**입력이 직업명이 아니라 내 업무 목록이다.** 같은 공개 데이터를 써도 내 시간표 위에 얹으면 결과가 달라진다.

### 3.2 경쟁 대안 대비 (`경쟁사_비교분석.md` 요약)

| 대안 | 그들의 답 | 우리의 답 |
|---|---|---|
| 직업 노출도 계산기 (Kickresume, aijobimpactcalculator 등) | 직업명 → 위험도 % | 업무 목록 → 맡길 일 / 지킬 일 |
| careeragents.org (가장 근접) | 업무 슬라이더 → 안정성 점수 | 점수에서 멈추지 않고 **시간·돈으로 번역** |
| TheGreatDisplacement.ai | "몇 년 뒤 대체" 연도 제시 | 연도·확률 안 찍음. **먼저 바뀔 것 1~2개**만 |
| Coursiv 습관 진단 | 일반 습관 → 코스 판매 깔때기 | 내 업무 위에서 측정. **강의를 팔지 않음** |
| 강의·국비과정·유튜브·서적 | "어떻게 하는지" | **"뭘 먼저 할지."** 학습의 앞단에 섬 |
| ChatGPT에 직접 묻기 | 대화형 일반론 | 구조화된 결과물 + 공유 가능한 카드 |
| 아무것도 안 함 | — | 3분·무료·타이핑 0 |

### 3.3 포지셔닝

- 메인: **"직업이 아니라, 당신의 일주일을 진단합니다."**
- 보조: **"3분이면, 이번 주에 되찾을 수 있는 시간이 나옵니다."**
- 예비(교육 연계 시): **"뭘 배울지 정하기 전에, 뭘 맡길지부터."**

### 3.4 확정된 원칙 6가지

1. 교육이 아니라 **진단**으로 푼다
2. 절감량은 **추정치로 표시**한다 — 확정 금액·연도는 쓰지 않음
3. 타깃은 A·B **두 갈래, 엔진은 공용**
4. 근거는 **요약만 공개**, 매핑표 전체는 비공개 (모방 방지)
5. **네트워크 확산을 제품 안에 심는다** — 궁합(엔진) + 지목(보조)
6. **진단 결과 앞에는 게이트를 걸지 않는다.** 단 **궁합 결과는 이메일로만 발송**한다 — 확산 장치의 대가로 연락처를 받는 교환

### 3.5 네트워크 설계 — 재미와 확산의 축

혼자 보는 진단은 한 번 보고 끝난다. 둘이 겹쳐 보면 대화가 생긴다.

| 장치 | 내용 | 역할 |
|---|---|---|
| **궁합 (안 1)** | 내 결과 링크 → 상대도 진단 → **두 사람의 업무 지도를 겹쳐서** 표시. "둘 다 자동화 안 하는 일", "당신 약점을 상대가 커버하는 부분" | **엔진.** 확산 + 이메일 확보 + 재미 |
| **지목 (안 3)** | 결과 말미에 "당신 업무 중 ○○는 AI가 잘하는 일. 주변에 아직 손으로 하는 사람 있죠?" + 보낼 문장·링크 | **보조.** 마찰 0, 톤 유지 |

**채택하지 않은 안**: 초대 잠금(결과 일부를 가리고 초대해야 열림). 확산력은 가장 세지만 "무료·가입 없음" 약속과 충돌하고, 억지로 보내진 링크는 신뢰를 깎는다.

**궁합이 US-8과 다른 점**: "시장에서 내 위치"는 전체 응답이 쌓여야 성립해 범위에서 제외했지만, 궁합은 **둘만 있으면 성립**한다. 그래서 사용자 100명 단계에서도 작동한다.

**이메일 확보 (3지점)**

| 지점 | 명분 | 성격 |
|---|---|---|
| S8a 궁합 초대 | "겹쳐 본 결과를 메일로 보내드릴게요" | **필수** — 궁합 결과는 이메일로만 발송 |
| S8b 초대 수락 | 초대받아 진단한 쪽도 결과를 받아야 함 | **필수** — 한 번의 궁합에서 이메일 2건 |
| S9 결과 하단 | "2주 뒤 비교 리포트" / "주간 한 줄" 구독 | 선택 |

**"가입 없음" 약속은 철회한다.** 랜딩 배지에서 문구를 빼고, 대신 "타이핑 없음 · 3분 · 무료"로 대체한다. 진단 본체는 여전히 이메일 없이 끝까지 볼 수 있으므로 "무료"는 유효하다.

**대가**: 궁합 초대 수락률이 떨어질 수 있다. 초대받은 사람 입장에서는 "친구가 보낸 링크인데 이메일을 요구한다"가 되기 때문이다. **초대→완주 전환율을 최우선 지표로 두고, 급락하면 초대받은 쪽만 이메일을 면제하는 안으로 되돌린다.**

### 3.6 디자인 원칙 (경쟁사 실측 반영)

경쟁사 두 곳을 직접 열어 확인한 결과를 반영한다.

**관찰**
- careeragents.org: 슬라이더 8개가 **한 화면**, 점수는 즉시 갱신. 단계 나눔도 로딩도 없음. 결과는 점수 + 밴드 + 실행 항목 3개
- aijobimpactcalculator.com: 결과 3패널(노출도 / 태스크 / **무엇이 성장 중인가**). "다른 계산기는 위험만 보여주지만 이 도구는 성장하는 것을 **위험 점수 옆에 나란히, 묻어두지 않고** 보여준다"를 차별점으로 선언. 퍼센트 대신 4단계 밴드 — "지어낸 정밀도"를 피하기 위해. 직업별 **사전 렌더링 공유 카드** 보유. 테마색은 따뜻한 오프화이트

**반영 결정**

| # | 결정 | 근거 |
|---|---|---|
| D1 | **S5 인위적 로딩 제거** | 경쟁사는 즉시 갱신을 강점으로 내세움. 지연은 검증 안 된 통념이고 이탈 지점만 늘림 |
| D2 | **S2 + S3 한 화면 통합** — 체크하면 그 자리에서 슬라이더 펼침 | 경쟁사는 슬라이더 8개도 한 화면에서 처리. 단계 하나 축소 |
| D3 | **절감량을 범위로 표시** — "주 6.5시간" → **"주 5~8시간"** | 소수점은 지어낸 정밀도. 원칙 2(추정치)와 정합 |
| D4 | **"당신만 할 수 있는 일"을 위로, 색으로 강조.** "맡길 일"은 아래 중립색 | 강점을 묻어두지 않는다. 현재 2단 배치는 위험 쪽이 시각적으로 우세 |
| D5 | 유형 카드 + 숫자를 **한 블록으로 합쳐 캡처 한 장에** | 결과 7섹션이 세로로 길어 첫 화면에 훅이 안 들어옴 |
| D6 | 공유 카드는 **동적 생성 대신 유형별 사전 제작** 지향 | 유형이 16개뿐이라 사전 제작이 가능. 동적 OG 난이도 대폭 감소. **단, 유형 체계 확정 후 착수** |
| D7 | **종이 질감 레이아웃.** 카드·색 블록 없이 크림 배경 + 가로선 + 여백으로만 위계 구성. 네온·다크·그라데이션 금지 | 신뢰 문제(불편함 5)에 대한 디자인 차원의 답. 스타트업이 아니라 인쇄된 리포트로 읽히게 |

**색상 — 딥 인디고 단색**

| 항목 | 값 | 용도 |
|---|---|---|
| 배경 | 크림 `#F4F2EC` | 전체 캔버스 |
| 구분선 | `#DCD8CC` 1px | 섹션 구분. 카드 대신 이것만 사용 |
| 메인 | 딥 인디고 `#26215C` | 절감 시간 숫자, "당신만 할 수 있는 일" 항목, 버튼 배경 |
| 보조 | `#534AB7` | 링크·보조 액션 텍스트 |
| 본문 | `#2C2C2A` / `#55524B` | 제목 / 본문 |
| 흐린 텍스트 | `#8A857A` / `#A9A497` | 라벨 / 캡션·수치 |

**적용 원칙**
- **색 블록(파스텔 배경 채우기)을 쓰지 않는다.** 색은 텍스트와 버튼에만
- 강조는 색 면적이 아니라 **글자 크기·굵기·여백**으로
- 유형 이름은 세리프(`--font-voice`)로 뽑아 리포트 느낌을 만든다
- "맡겨도 되는 일"은 무채색으로 두어, 강조가 강점 쪽에 남게 한다 (D4와 연동)

**제외한 색과 이유**: 파랑(계산기·SaaS 기본값) · 틸(헬스케어·핀테크 인접) · 코랄/앰버(경고색 연상). 딥 인디고는 보라 계열이라 AI 서비스 인상이 남을 수 있으나, **면적을 최소화하고 크림 배경에 얹는 방식이라 그 인상이 희석된다.**

### 3.7 재미와 확산 장치

**전제**: 이 진단은 구조적으로 한 번 하면 끝난다. 업무 구성은 몇 달에 한 번 바뀔까 말까 하기 때문이다. 그러므로 재방문 장치는 위에 억지로 얹는 것이 아니라, **결과가 바뀔 이유**를 만들어야 한다.

#### 추천을 만드는 것

| # | 장치 | 내용 | 개발 비용 |
|---|---|---|---|
| F1 | **궁합** | 이미 채택 (3.5). 확산의 엔진 | 큼 |
| F2 | **반박 버튼** | 결과 하단에 "이거 안 맞는데요" → 어느 부분이 틀렸는지 고르고 다시 계산. MBTI가 퍼진 이유는 정확해서가 아니라 **"이거 나 아닌데?"라고 말하고 싶어져서**다. 결과를 들고 대화를 시작하게 만든다. 동시에 **정확도 개선 데이터**가 쌓인다 | 작음 |
| F3 | **의외의 한 줄** | 결과 중 딱 한 줄만 "어떻게 알았지" 소리가 나오게. 예: "정산에 주 2시간 쓰시죠. 이거 아직 손으로 하는 프리랜서는 이제 얼마 안 남았어요". **전체를 정확하게 만들려 하지 말고 한 줄에 집중** | 중간 |
| F4 | **유형 이름의 질** | 자조 섞인 이름("조용한 정비공")이 분류형 이름("AI 활용 초급자")보다 훨씬 잘 퍼진다. 스스로를 놀릴 수 있어야 하고, **16개 중 나쁜 유형이 하나도 없어야** 한다. 별도 문서 `유형16.md` | 0 (이미 만들 것) |

#### 재방문을 만드는 것

| # | 장치 | 내용 | 주의 |
|---|---|---|---|
| F5 | **"지난번보다"** | 2주 뒤 재진단 → 되찾은 시간 변화 비교. 이메일 수집의 명분이자 재방문 이유 | 실행한 사람만 숫자가 변한다. 안 변한 사람에겐 실망이 될 수 있음 — 문구를 비난조로 쓰지 말 것 |
| F6 | **주간 한 줄** | "이번 주엔 이것만" 미션 하나를 메일로 | 앱을 안 열어도 되어 부담이 없음. 발송 빈도는 주 1회 상한 |

#### 채택하지 않은 것

| 장치 | 제외 이유 |
|---|---|
| 뱃지·연속 기록·포인트 | 진단 도구에 게임 요소를 붙이면 신뢰가 깎인다. "레퍼런스 자료"로 읽히려는 방향(D7)과 충돌 |
| 랭킹·리더보드 | "AI 잘 쓰는 순위"는 불안 마케팅. 피하기로 한 공포 톤으로 회귀 |
| 푸시 알림 | 웹에서 구현이 어렵고, 되더라도 이탈 요인 |

**착수 순서**: F4 → F2 → F3 → F5 → F6. F4는 추가 개발이 0이고, F2는 버튼 하나로 효과가 크다.

## 5. 핵심 흐름 — 고객 경험 5단계

무료 진단이므로 등록·결제·수강·졸업 단계는 없다. 대신 유입에서 재방문까지 5단계로 본다.

### 단계 1. 관심

- **상황**: "AI가 내 일 어떻게 바꾸지"가 궁금해진 순간. 또는 남의 결과 카드를 봤을 때
- **채널**: 블로그(일상노트) 후기 글, 진단 참여자의 공유 카드, 커뮤니티, 검색
- **목표**: 클릭
- **이탈 요인**: 또 하나의 AI 테스트로 보임
- **대응**: 공유 카드에 **유형 이름 + 주 N시간**이 함께 보이게. 숫자가 훅
- **지표**: 카드 노출 → 클릭률

### 단계 2. 랜딩 방문 (S0)

- **목표**: 5초 안에 "필요하고 안 귀찮다" 전달 → 시작 버튼
- **이탈 요인**: 설명이 길다, 가입을 요구한다, 뭘 얻는지 모르겠다
- **대응**: 헤드라인 1 + 보조 1 + 배지("타이핑 없음·가입 없음·무료") + CTA 1 + 결과 예시 이미지
- **지표**: 랜딩 → 시작 클릭률

### 단계 3. 진단 완주 (S1~S4)

- **목표**: 이탈 없이 끝까지
- **구조 변경(D1·D2)**: S2와 S3를 한 화면으로 통합, S5 인위적 로딩 제거 → **화면 수 축소**
- **최대 위험 지점**: 통합된 업무 입력 화면. 업무 4개면 조작 8회
- **대응**
  - 체크하면 그 자리에서 슬라이더 펼침. 슬라이더 기본값·AI 사용 "조금" 기본 선택 → 그냥 넘겨도 결과 나옴
  - 합계 시간이 상단에서 **즉시 갱신**
  - 업무 상한 **4개 권장** (프로토타입에서 5개는 스크롤 과다 확인)
  - E1 이탈 방지 시트 1회
  - 직종 미발견은 조용한 이탈 → 미발견 비율 계측
- **지표**: 화면별 이탈률. 완주 시간 중앙값 3분 이내

### 단계 4. 결과 확인·공유·지목 (S6, S7)

- **목표**: "맞네" → 저장·공유·지목
- **성패 구간**: **S6-2 "내 일주일"**. 여기서 안 맞으면 아래 섹션 전체가 무너짐
- **대응**
  - **유형 + 절감 범위를 한 블록으로** 최상단에 배치 → 캡처 한 장에 훅이 들어옴 (D5)
  - **"당신만 할 수 있는 일"을 먼저, 딥 인디고로.** "맡겨도 되는 일"은 아래 무채색 (D4)
  - 절감량은 **범위 표기** — "주 5~8시간" (D3)
  - "추정치입니다" 명시, 근거 요약 링크 1줄
  - 확정 금액·대체 연도·공포 문구 금지
  - 공유 이미지·공개 결과 페이지에 개인 업무명 원문 노출 금지
  - **결과 고유 URL `/r/{id}`.** 공유 카드는 유형별 사전 제작 지향 (D6)
  - 이미지 3종: 9:16 / 1:1 / OG. **모바일 우선**
  - 지목 카드로 US-12 충족
- **지표**: 결과 도달률, 스크롤 완료율, 이미지 저장률, 공유 클릭률

### 단계 5. 궁합 → 재방문 (S8, S9)

- **목표**: 초대 → 상대 완주 → 겹쳐 본 결과 → 양쪽 모두 재방문
- **이메일 확보**: S8a·S8b **필수**(궁합 결과는 메일 전용) + S9 선택("2주 뒤 비교", 주간 한 줄 구독). **진단 본체 앞에는 게이트를 걸지 않는다**
- **대기 UX**: 상대가 진단을 안 하면? — 미결. 며칠 뒤 리마인드 1회 정도가 상한
- **현재 범위**: 강의·상품 판매 없음. 다음 걸음 1개만 제시
- **향후 지불 지점 후보** (검증 후 결정)
  - A: 자동화 셋업 대행
  - B: 업무 기반 이력서·포지셔닝 재작성
- **지표**: 궁합 초대 발송 수 → 수락 완주 수 → 전환율, 이메일 수집률, 2주 내 재방문율

## 9. 착수 순서

**기준 결정**: 코드가 아니라 **문서(이 PRD)에 맞춘다.** 현재 코드는 "MBTI + 하루 루틴" 기반으로, 경쟁사 분석에서 차별점 없음으로 판단한 영역이다. PRD의 차별점 전체가 "입력이 직업명이 아니라 내 업무 목록"(3.1)에서 나오는데 코드에는 그것이 없다.

**코드에서 가져올 것**: 결과 화면 골격 · 공유 · 관리자 대시보드 · Supabase 스키마 일부. 경제가치 환산(일/월/연 금액)은 아이디어를 살리되 **확정 금액 대신 범위·실물 환산으로 변환**한다(D3, 원칙 2).

**코드에서 버릴 것**: 페이월 게이트(`ResultDashboard`의 blur 잠금) — 원칙 6 위반. 완주율과 확산이 함께 무너진다. MBTI 축(`PERSONA_MAP`) — 제3의 축이며 차별점을 흐린다.

| 순서 | 작업 | 이유 |
|---|---|---|
| 1 | **RLS 3건 수정 (R1~R3)** | 지금 열려 있는 실제 취약점 |
| 2 | **이벤트 로깅 스키마 확정** | 소급 불가. 재작업 전에 심어야 함 |
| 3 | **확인후보 9개 자료 조사** | 인터뷰 없이 처리 가능. 특히 데이터 라이선스 |
| 4 | **인터뷰** — A 3명 + B 3명. 불편 4를 첫 질문으로 | 세그먼트 섞지 말 것 |
| 5 | **직종 × 업무 프리셋 매트릭스** | 가장 큰 작업. 인터뷰의 실제 업무명 반영 |
| 6 | **입력부 교체** — `RoutineInput`+`MBTIGrid` → S1~S4 | **차별점의 전부** |
| 7 | **분류 엔진 교체** — `PERSONA_MAP` → 노출도 × 활용도 16유형 | `유형16.md` 기준 |
| 8 | 페이월 제거 · 색/레이아웃(D7) · 결과 재구성(D3~D5) | |
| 9 | 궁합(S8) · 이메일 · 공유 3종 | |
| 10 | 지인 10명 완주율·정확도 테스트 → 소규모 공개 | |

**이미 끝난 것**: `/admin` 인증 (클라이언트 가드 + DB RLS). 단 `user_roles`에 실제 admin 계정이 등록돼 있는지는 **미검증** — 로그인 한 번 해볼 것.
