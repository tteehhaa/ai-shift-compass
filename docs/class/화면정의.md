# 화면정의 — AI Life Shift

작성일: 2026-09-08
기준 설계: `ai-life-shift-v3-통합설계.md`

## 1. 유저 스토리 10개

### A. 프리랜서·1인사업자

**US-1**
프리랜서로서, 나는 **일은 많은데 수입이 안 늘어서** AI Life Shift가 **내 업무 중 돈이 안 되는 데 시간을 쓰고 있는 곳을 찾아 주기**를 원한다.

**US-2**
1인사업자로서, 나는 **AI 도구가 너무 많아 뭐부터 붙일지 몰라서** AI Life Shift가 **내 업무 5개 중 어느 것부터 자동화하면 효과가 큰지 순서를 정해 주기**를 원한다.

**US-3**
프리랜서로서, 나는 **시간이 곧 매출이라서** AI Life Shift가 **아낄 수 있는 시간을 "이번 주에 한 건 더"처럼 내 일 단위로 환산해 주기**를 원한다.

**US-4**
1인사업자로서, 나는 **혼자라 정산·행정에 시간을 뺏겨서** AI Life Shift가 **내가 직접 해야만 하는 일과 손 떼도 되는 일을 갈라 주기**를 원한다.

**US-5**
프리랜서로서, 나는 **진단만 받고 끝나면 소용없어서** AI Life Shift가 **다음에 뭘 할지 한 가지만 콕 집어 주기**를 원한다.

### B. 이직을 준비하는 직장인

**US-6**
이직 준비 중인 직장인으로서, 나는 **내 경력 중 AI로 대체될 부분이 걱정돼서** AI Life Shift가 **내 업무 중 AI에 밀리지 않는 것이 무엇인지 알려 주기**를 원한다.

**US-7**
이직 준비 중인 직장인으로서, 나는 **이력서에 뭘 앞세워야 할지 몰라서** AI Life Shift가 **내 업무를 "AI가 못 하는 일" 기준으로 정렬해 주기**를 원한다.

**US-8**
이직 준비 중인 직장인으로서, 나는 **지금 회사에서 배울 게 없는 것 같아서** AI Life Shift가 **내 업무 구성이 시장에서 어느 위치인지 짚어 주기**를 원한다.

**US-9**
이직 준비 중인 직장인으로서, 나는 **어떤 스킬을 지금 배워야 할지 몰라서** AI Life Shift가 **강의를 팔지 않고 "무엇부터"만 알려 주기**를 원한다.

### A·B 공통

**US-10**
바쁜 사람으로서, 나는 **길고 복잡한 설문에 지쳐서** AI Life Shift가 **타이핑 없이 3분 안에 끝내고 결과를 이미지 한 장으로 저장하게 해 주기**를 원한다.

**US-11** (네트워크 — 궁합)
같은 일을 하는 동료·친구가 있는 사람으로서, 나는 **내 결과만으로는 이게 좋은 건지 나쁜 건지 모르겠어서** AI Life Shift가 **그 사람 결과와 내 결과를 나란히 겹쳐 보여 주기**를 원한다.

**US-12** (네트워크 — 지목)
진단을 끝낸 사람으로서, 나는 **주변에 이걸 아직 손으로 하는 사람이 떠올라서** AI Life Shift가 **그 사람에게 보낼 만한 한 문장과 링크를 만들어 주기**를 원한다.

## 3. 화면별 정의

### S0. 랜딩

- **목적**: 5초 안에 "이건 나한테 필요하고, 안 귀찮다"를 전달
- **구성**
  - 헤드라인: "직업이 아니라, 당신의 일주일을 진단합니다"
  - 보조: "3분이면, 이번 주에 되찾을 수 있는 시간이 나옵니다"
  - 신뢰 배지: "타이핑 없음 · 3분 · 무료"
  - CTA 버튼 1개: "진단 시작"
  - 하단: 결과 예시 이미지 1장 (실제 결과 화면 축소)
- **금지**: 서비스 설명 문단, 로그인, 이메일 수집
- **주의**: 결과 예시를 보여줘야 이탈이 준다는 건 가설 (확인 필요)

### S1. 직종 선택

- **목적**: 업무 프리셋 호출
- **구성**
  - 질문: "어떤 일을 하고 계세요?"
  - 칩 형태 직종 15~20개 (2열 그리드)
  - 검색창 (칩에 없을 때만 사용, 기본은 숨김)
  - 하단 진행 표시 "1 / 3"
- **입력**: 클릭 1회
- **엣지**: 직종이 없으면 "비슷한 것 선택" 안내 → 가장 가까운 프리셋. 이탈 지점이므로 초기 직종 목록 선정이 중요
- **주의**: 직종을 못 찾은 사용자 비율을 반드시 계측할 것

### S2. 업무 체크

- **목적**: 내 업무 확정 — **차별점의 핵심 화면**
- **구성**
  - 질문: "이 중에 실제로 하는 일을 골라 주세요"
  - 프리셋 업무 8~10개, 체크박스 카드
  - "+ 직접 추가" (선택, 타이핑 발생하므로 눈에 안 띄게)
  - 선택 개수 표시: "3개 선택됨 · 3~5개 권장"
  - 다음 버튼 (1개 이상 선택 시 활성)
- **입력**: 클릭 3~5회
- **상한**: 최대 7개까지. 그 이상은 S3가 무거워짐
- **엣지**: 0개 선택 시 다음 비활성 + "하나만 골라도 돼요"

### S3. 시간 + AI 활용도

- **목적**: 절감 계산의 두 축
- **구성** (선택한 업무마다 카드 1개, 세로 스크롤)
  - 업무명
  - 슬라이더: 주당 시간 (0.5~40h, 스냅 단위 크게)
  - 3택 탭: AI 사용 — "안 씀 / 조금 / 많이"
  - 상단 누적 표시: "합계 주 18시간"
- **입력**: 드래그 + 탭, 업무당 2회
- **설계 주의**: 이 화면이 가장 무겁다. **업무 5개 × 2입력 = 10회 조작.** 완주율 계측 필수, 이탈 시 업무 상한을 5개로 낮출 것
- **기본값**: 슬라이더는 중앙값 프리셋, AI 사용은 "조금" 기본 선택 → 그냥 넘겨도 결과가 나오게

### S4. 목적 선택 (A/B 분기)

- **목적**: 결과 문구 톤 결정
- **구성**
  - 질문: "이 진단으로 뭘 알고 싶으세요?"
  - 2택 큰 버튼
    - "일을 줄이고 수입을 늘리고 싶어요" → **A 트랙**
    - "이직·전환을 준비 중이에요" → **B 트랙**
  - "둘 다 / 잘 모르겠어요" 작게 → A 트랙 기본
- **입력**: 클릭 1회
- **주의**: 이 한 화면이 결과의 절반을 가른다. 문구를 계속 다듬을 것

### S5. 계산 중

- **목적**: 대기 이탈 방지
- **구성**: 진행 바 + 단계 문구 3개
  - "업무를 정리하는 중"
  - "공개 지표와 맞춰 보는 중"
  - "결과를 만드는 중"
- **길이**: 2~4초. 계산은 대부분 규칙 기반이라 실제로는 즉시 끝남 → **의도적 지연**. 너무 빠르면 신뢰가 떨어진다는 통념이 있으나 검증 안 됨 (확인 필요)

### S6. 결과 — 핵심 화면

세로 스크롤, 섹션 7개.

| 순서 | 섹션 | 내용 | 스토리 |
|---|---|---|---|
| 1 | 유형 카드 | 16유형 중 하나. 이름 + 한 줄. **여기까지가 캡처 한 장에 들어와야 함** | US-10 |
| 2 | 내 일주일 | 체크한 업무와 시간 시각화. "맞네" 구간 | US-1 |
| 3 | 업무 지도 | 좌: 맡겨도 되는 일 / 우: 당신만 할 수 있는 일 | US-4, US-6, US-7 |
| 4 | 되찾을 시간 | **주 N시간**, 큰 숫자 하나. 바로 아래 "추정치입니다" 명시 | US-3 |
| 5 | 그래서 뭘 | A: "한 주에 한 건 더" 식 환산 / B: "이력서에 앞세울 것" | US-3, US-7, US-8 |
| 6 | 먼저 바뀔 것 | 노출도 최상위 업무 1~2개. 연도·확률 표기 금지 | US-6 |
| 7 | 다음 한 걸음 | **딱 하나만.** 강의 판매 링크 없음 | US-5, US-9 |

- **언어 규칙**: "노출도" → "AI에 맡겨도 되는 일" / "시간 압축 지수" → "되찾을 수 있는 시간" / "자동화" → "손 떼도 되는 부분"
- **근거 표기**: 하단 1줄 — "공개 지표를 참고해 산출한 추정치입니다" + 요약 근거 페이지 링크. **매핑표 전체는 비공개**
- **금지**: 확정 금액("월 ○○만원"), 대체 연도, 공포 문구

### S7. 공유 + 지목

- **목적**: 확산. **모바일 우선으로 설계** — 공유는 거의 전부 모바일에서 일어남
- **구성**
  - 결과 이미지 3종 자동 생성
    - 9:16 (인스타 스토리)
    - 1:1 (피드)
    - 1.91:1 (카톡·링크 미리보기용 OG)
  - "이미지 저장" / "결과 링크 복사"
  - "블로그에 올리기" → 복붙용 HTML 블록
  - **지목 카드 (US-12)**: "당신 업무 중 ○○는 AI가 잘하는 일이에요. 주변에 아직 손으로 하는 사람 있죠?" + 그대로 보낼 수 있는 한 문장 + 링크
- **결과 URL**: `/r/{id}` — **랜딩이 아니라 내 결과 페이지로 연결.** 남이 열면 결과를 보고 하단에 "나도 해보기"
- **동적 OG 태그**: 결과별로 유형 이름 + 주 N시간이 미리보기에 노출. **미리보기가 안 뜨면 공유는 사실상 죽는다** — 구현 난이도 있으므로 초기부터 확보
- **주의**: 이미지·공개 결과 페이지에 개인 업무명 원문 노출 금지. 요약·범주명으로 치환

### S8. 궁합 (US-11) — 네트워크 엔진

**S8a. 궁합 초대**

- **위치**: S6 결과 하단 + S7
- **문구**: "같은 일 하는 사람과 비교해 보세요"
- **동작**: 초대 링크 생성 → 카톡·메신저로 전송
- **이메일 확보 지점**: "겹쳐 본 결과를 메일로 보내드릴게요" → 이메일 입력
  - **필수.** 궁합 결과는 이메일로만 발송한다
  - 건너뛰면 초대 링크 자체가 생성되지 않음

**S8b. 궁합 결과**

- **진입**: 초대받은 사람이 진단 완주 → **이메일 입력** → 양쪽 모두에게 메일 발송
- **이메일 확보 지점 2**: 초대받은 쪽도 결과를 받아야 하므로 필수. **궁합 1건당 이메일 2건**
- **구성**
  - 두 사람의 업무 지도를 나란히
  - "둘 다 자동화 안 하고 있는 일" — 공통 미개척 영역
  - "당신이 약한 걸 상대가 커버하는 부분"
  - 궁합 한 줄 (유형 조합별 문구)
- **주의**: 상대의 업무 상세는 요약 수준만. 원문 노출 금지
- **위험**: 초대받은 사람 입장에서 "친구가 보낸 링크인데 이메일을 요구한다"가 됨. **초대→완주 전환율을 최우선 지표로 감시.** 급락 시 초대받은 쪽만 면제하는 안으로 되돌림
- **데이터**: 전체 사용자 통계가 없어도 **둘만 있으면 성립.** US-8(시장 내 위치)과 달리 초기부터 작동하는 이유

### S9. 이메일 — 선택 구독

- **위치**: S6 결과를 **전부 본 뒤** 하단
- **항목 2개 (체크박스)**
  - "2주 뒤 다시 해보고 얼마나 바뀌었는지 비교해 드릴게요" (F5)
  - "이번 주엔 이것만 — 주간 한 줄 받기" (F6)
- **금지**: 진단 결과 앞에 게이트 걸기. 완주율이 무너짐
- **표기**: 수집 목적·보관 기간·수신 거부 방법 명시

### E1. 이탈 방지 시트

- **발동**: S2·S3에서 뒤로가기 또는 30초 무동작
- **내용**: "여기까지 왔는데 아깝잖아요. 30초면 끝나요" + 계속 / 나가기
- **주의**: 과하면 역효과. 1회만 노출

### ADM. 관리자

- **접근**: 인증 **구현 완료** — 클라이언트 가드(세션 + `user_roles` role 재검사) + DB단 `has_role()` security-definer RLS. 클라이언트 가드를 우회해도 데이터가 나오지 않음. 단 실제 admin 계정 등록 여부는 미검증

**순위 지표 (요청 사항)**

| 순위표 | 무엇을 알 수 있나 |
|---|---|
| 유형별 분포 순위 | 결과가 어디로 쏠리는지. 한쪽 편중이면 계산 로직 재조정 신호 |
| 직종별 참여 순위 | 실제로 누가 오는지. 프리셋 우선순위 |
| 가장 많이 체크된 업무 순위 | 공통 업무 파악 |
| **"맡길 일"로 판정된 업무 순위** | **사람들의 다음 관심사.** 다들 자동화하고 싶어 하는 것 |
| AI 활용도 "안 씀" 비율 상위 업무 | 미충족 수요. 다음 제품의 힌트 |
| 직종 미발견 검색어 순위 | 프리셋에 추가할 직종 |

**운영 지표**
- 화면별 이탈률 (특히 S2 → S3)
- 평균 선택 업무 수 / 완주 시간
- A/B 트랙 비율
- 공유 클릭률 / 이미지 저장률
- **궁합 초대 발송 수 → 수락 완주 수 → 전환율**
- 이메일 수집률

**선행 요건**: 이벤트 로깅 설계가 아직 없음. 화면 진입·이탈·클릭 이벤트를 **처음부터** 심어야 함 — 소급 불가

---

## 4. 화면 흐름

```
S0 랜딩
 └→ S1 직종        (클릭 1)
     └→ S2 업무 체크 (클릭 3~5)   ←─ E1 이탈 방지
         └→ S3 시간·활용도 (조작 6~10)  ←─ E1
             └→ S4 목적 (클릭 1)
                 └→ S5 계산 중 (2~4초)
                     └→ S6 결과  →  S9 이메일 (선택)
                         ├→ S7 공유 + 지목
                         └→ S8a 궁합 초대 ──→ [상대가 진단] ──→ S8b 궁합 결과
                                                                    ↑
                                                          양쪽 모두에게 노출
```

**총 조작 12~18회, 타이핑 0회(이메일 제외), 목표 3분 이내.**

**단일 페이지 구조**: S0~S9 전체가 랜딩 페이지 하나(SPA)에서 화면 전환으로 처리된다. 예외는 두 곳 — 공유용 결과 페이지 `/r/{id}`와 궁합 결과 `/p/{id}`는 고유 URL을 가져야 한다. 공유할 대상이 없으면 확산이 성립하지 않기 때문.

| 스토리 | 대응 화면 | 충족 여부 |

| US-1 돈 안 되는 곳 찾기 | S6-2, S6-3 | ✅ |
| US-2 자동화 순서 | S6-3 | ✅ |
| US-3 매출 환산 | S6-4, S6-5(A) | ⚠️ 환산 방식 미정 |
| US-4 직접 할 일 구분 | S6-3 | ✅ |

| US-8 시장 위치 | — | ❌ **대응 화면 없음.** 비교 기준 데이터가 없어 현재 구현 불가 |
